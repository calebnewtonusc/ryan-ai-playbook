# Research the craft

Knowing how to drive the tool is not the same as knowing what good looks like.
This skill makes the second part happen first.

## Steps

1. **Name the genre.** "A volunteer sign-up form", "a Sunday announcement
   email", "a landing page for a church app".
2. **Find three strong examples and one teardown.** A teardown is a
   professional explaining why something works. Search for "<genre> teardown",
   "<genre> best practices", "<genre> mistakes". Prefer people who make these
   for a living over listicles.
3. **Extract rules, not vibes.** Write 5 to 10 rules you could check a draft
   against. "One call to action above the fold" is a rule. "Make it pop" is not.
4. **Save the rules** in the project's `CLAUDE.md` under a heading for the
   genre, so every later session uses them.
5. **Build, then check the draft against each rule** and say which ones it
   passes.

## When the request breaks a rule

Say which rule in one line, build the version that follows it, and offer the
literal version as an alternative.

## Check the premise

If the idea depends on a claim like "nothing like this exists", search for it
first. Report what exists, with links, and where the real gap is.

## For someone learning

Write your own guess at the rules before reading the examples. The difference
between your list and the professionals' list is the lesson.
