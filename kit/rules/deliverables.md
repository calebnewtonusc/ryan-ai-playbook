# Deliverables

How to hand someone a file they will actually use.

## Where and what format

- **Save it where they will find it** (Downloads or the project folder), with a
  name a person would type: `Volunteer schedule draft.md`, not
  `output_final_v3.md`.
- **They might edit it:** Markdown (`.md`) or a Google Doc.
- **A team will edit it together, or it goes on a call:** a Google Doc or Sheet.
- **It goes to someone outside** (a pastor, a vendor, a board): PDF.
- **A one-page document has to fit on one page.** Check the page count before
  handing it over. Cut lines rather than shrinking the type.

## Shape follows how it gets used

- **Used live** (a meeting, a call, a walkthrough): number the sections in the
  order things happen, and write lines as what to say or do at that moment.
- **Used for reference** (a plan, a process doc): group it by the question the
  reader will come in with.
- **One glance per line.** Short bullets with space between them. A dense
  block becomes a wall of text.
- **Plain English for anyone else.** Full words, every insider term explained
  once.

## Check it as the reader would

Read every line as the person holding it. A line that contradicts another line
gets fixed before it goes out. Before saying something is "ready to send," open
every attachment and read it as the recipient.

## A how-to guide people will pass around

- Written for the least technical reader. Every account they create gets one
  line on what it is for. Every command gets one line on what it does.
- Every tool and page is a link.
- Real hierarchy: a title, numbered sections, code in a monospace block.
- Test it the way a stranger would, on a machine that has not been set up.
